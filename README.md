# SferaDecompiler — генератор нативного C17

Проект восстанавливает функции PE32/x86 и генерирует для них обычные C-функции. Декодированные инструкции используются только во время Python-анализа и не попадают в исполняемый проект. В сгенерированном рантайме отсутствуют таблицы инструкций, диспетчер опкодов и цикл пошагового исполнения.

Прямые внутренние вызовы становятся символьными вызовами `sfera_sub_*`, импорты через IAT — вызовами `sfera_import_*`. Непрямые вызовы разрешаются только по восстановленным точкам входа функций; таблица разрешения содержит адреса функций, а не инструкции или их семантику.

Вход каждой C-функции закреплён явным переходом на восстановленный entry-блок. Это сохраняет порядок исполнения для функций, которые используют общие хвосты с меньшими адресами.

Распознанные библиотечные идиомы нормализуются во время генерации. В частности, построение ключей `NEW_FONT_n` больше не проходит через `std::iostream`, а поиск значения в загруженном `.ui` восстановлен как ограниченная C-функция с исходным `ret 4`. Адреса хранилища и точка вызова обнаруживаются по форме кода; неоднозначное распознавание останавливает генерацию.

## Генерация и сборка

Требуются Python 3.10+, Visual Studio 2022 с компонентом Desktop development with C++ и платформа Win32.

```bat
py -3 -m pip install -r requirements.txt
run_sfera.cmd
Sfera\out\build_release.cmd
```

Готовая программа и DLL появятся в `Sfera\out\bin\Release`. Сгенерированные файлы `lifted_functions_*.c` компилируются как C17; инфраструктура отображения PE и низкоуровневые ABI-мосты — как C++20/x86.

## ABI и память

Рантайм сохраняет исходные GPR, EFLAGS, x87, виртуальный FS/TEB и 32-битный стек. Один x86-мост обслуживает cdecl, stdcall, thiscall, fastcall, IAT-вызовы и обратные вызовы из нативных DLL. Смещения общей структуры `LiftCpu` зафиксированы compile-time проверками.

Данные PE и ресурсы отображаются в текущий процесс с применением `HIGHLOW`-релокаций. Исходные исполняемые секции не исполняются и остаются нулевыми, кроме восстановленных switch-таблиц, lookup-данных и пятибайтовых callback-стабов.

`GetModuleHandleA/W(nullptr)` и `GetModuleFileNameA/W` виртуализированы для совместимости клиента. Корень ресурсов определяется по `mbc\_main.mbc`; при необходимости задайте `SFERA_CLIENT_ROOT`. Расширенная диагностика включается переменной `SFERA_NATIVE_DEEP_TRACE=1`.

Сводка восстановления и автоматических проверок находится в `Sfera\out\report.json`.
