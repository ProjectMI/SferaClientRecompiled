# SferaDecompiler: исполняемый IR без исходного `.text`

Текущая итерация генерирует самостоятельный проект Win32/x86, который интерпретирует структурированный IR. Исходная исполняемая секция PE обнуляется до встраивания и во время запуска не восстанавливается. Нативными остаются сам рантайм, системные и комплектные DLL, а также короткие сгенерированные мосты callback-вызовов.

## Генерация и сборка

Требуются Python 3.10 или новее, Visual Studio 2022 с компонентом Desktop development with C++ и платформа Win32.

```bat
py -3 -m pip install -r requirements.txt
run_sfera.cmd
Sfera\out\build_release.cmd
```

Готовая программа и восемь требуемых DLL появятся в `Sfera\out\bin\Release`. Проект линкуется по фиксированной базе `0x20000000`, а дочерний процесс заранее резервирует исходный диапазон гостевого PE с базы `0x00400000`.

При F5 используется launcher с предварительным резервированием диапазона. Debug и Release компилируют горячий цикл с оптимизацией скорости; Debug сохраняет PDB и отладочную CRT. Перед запуском launcher ищет корень ресурсов по `mbc\_main.mbc`, передаёт его дочернему процессу как рабочий каталог и виртуализирует `GetModuleFileNameA/W` путём исходного guest EXE. Если ресурсы лежат вне дерева проекта, задайте полный путь к каталогу клиента в переменной `SFERA_GUEST_ROOT`. Visual Studio отлаживает launcher, поэтому стек исключения дочернего процесса следует открывать из создаваемого рядом с EXE файла `sfera_ir_crash.dmp` вместе с PDB текущей сборки.

## Устройство рантайма

| Область | Реализация |
|---|---|
| Декодирование | `iced-x86`, структурированные операнды и точное декодирование целей переходов |
| Управление | Индекс IR по гостевому EIP, внутренние `call/jmp/ret`, косвенные цели и импортные thunk-функции |
| ABI | cdecl, stdcall, thiscall и fastcall через x86-мост с сохранением GPR, EFLAGS, ESP, очистки аргументов и встроенной самопроверкой; импортная метаинформация управляет преобразованием гостевых псевдодескрипторов в нативные дескрипторы процесса |
| Нативный стек | Переключение на гостевой стек с временной синхронизацией `StackBase/StackLimit` в TEB |
| Callback | Пятибайтовые мосты по релокациям, отдельный гостевой стек и обратный перенос регистров/очистки стека |
| Состояние CPU | Частичные регистры, основные EFLAGS, строковые инструкции, x87, виртуальный FS и минимальный SSE |
| Семантические summaries | Поиск значения в уже загруженном конфиге и преобразование unsigned-индекса в VC10 `std::string` связываются заново при каждой генерации по структуре IR и использованию литерала `NEW_FONT_`; decimal-summary проверяет одновременно target и callsite, поэтому сдвиг функций в новой сборке EXE не оставляет старый адрес активным |
| PE | Заголовки, данные, ресурсы, IAT и DLL; исходные инструкции не копируются, а таблицы `switch` и все ограниченные индексные таблицы из `.text` восстанавливаются как данные; callback-мосты не перекрывают эти диапазоны |

`Sfera\out\report.json` фиксирует количество инструкций, покрытие CFG от точки входа, отсутствие недекодированных прямых целей, полноту покрытия ссылок на данные внутри исполняемых секций, найденные адреса semantic summaries, число импортов с преобразованием идентичности модуля и независимую проверку нулевого исполняемого payload. Если EXE содержит `NEW_FONT_`, а связку decimal-helper/callsite нельзя определить однозначно, генерация завершается диагностической ошибкой и не выпускает рантайм с предположительным адресом. Быстрый режим выполняет обращения к гостевой памяти напрямую и сохраняет текущую инструкцию, call stack и кольцевую IR-трассу для нативного crash-report. Переменная `SFERA_IR_DEEP_TRACE=1` включает защищённые пробы памяти и отслеживание происхождения каждой записи, которое требуется для подробного исследования воспроизводимого сбоя. Контролируемая ошибка интерпретатора создаёт `sfera_ir_guest_failure.txt` с гостевыми регистрами, точным IR-вызовом, интерпретированным call stack и 256 последними инструкциями. Штатные функции `BoundCheckArray` и клиентский fatal-handler перехватываются до аварийной очистки; для ошибки MBC отчёт дополнительно показывает исходный токен, адрес переменной, последнюю наблюдавшуюся IR-запись и количество перечисленных MBC-файлов. Ошибка загрузки шрифта дополнительно показывает последний ключ конфигурации, а успешные и отсутствующие `NEW_FONT_n` фиксируются в runtime-логе. Начало и завершение перечислений, открытия ресурсов и преобразования аргументов нативных импортов пишутся в `sfera_ir_runtime.log`. Нативное падение создаёт `sfera_ir_crash.txt` и `sfera_ir_crash.dmp`; текстовый отчёт также содержит гостевой call stack и расширенную IR-трассу.

## Проверки

```bat
py -3 -m unittest discover -s tests -v
```

В текущем окружении проверены генератор, CFG, отсутствие исходного кода в payload и синтаксис всех сгенерированных C++-единиц. На Windows рантайм до старта гостевой точки входа дополнительно прогоняет реальные cdecl/stdcall/fastcall-вызовы через тот же мост. Полная проверка клиента требует запуска Release/Win32-сборки. Пересечение границы интерпретатора нативным C++/SEH-исключением пока не поддерживается.
