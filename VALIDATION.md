# Проверка результата

Проверено на свежей генерации из `Sfera/sphereclient_patched.exe`:

- 4 893 определения C-функций, 4 893 прототипа и 4 893 записи таблицы непрямых вызовов совпадают;
- 412 импортов имеют отдельные символьные C-обертки;
- все 29 C17-файлов проходят GCC с `-Wall -Wextra -Werror -pedantic-errors`;
- C++20-рантайм проходит строгую portable-проверку с `-Wall -Wextra -Werror -pedantic-errors`;
- 29 C-объектов и три объекта рантайма успешно объединены в один relocatable object; неразрешенных `sfera_*` или `lift_*` символов нет;
- восстановлены C-нормализации поиска конфигурации `0x00401600` и построения десятичной SSO-строки в `0x004BC318`; тесты покрывают найденный и отсутствующий `NEW_FONT_n`, максимальное `uint32_t`, очистку хвоста SSO и исходный `ret 4`;
- 100 000 случайных 32-битных векторов для ADD/SUB-флагов и RCR сверены с аппаратным x86-64;
- статическая проверка подтверждает отсутствие дескрипторов инструкций, диспетчера семантики и пошагового цикла в выходном рантайме;
- исходные исполняемые секции во встроенном PE payload нулевые; нераспознанных ссылок на данные внутри них нет.
- конфигурации MSBuild разделены: Debug/Win32 использует `/Od`, `/RTC1`, `/MTd`, а Release/Win32 — `/O2`, без runtime checks, и `/MT`.
- все 4 893 C-функции имеют проверенный entry-переход; для 520 функций он перенаправляет исполнение через блоки с меньшими адресами, включая `0x004F5570 → 0x00421FC0`.

Release/Win32 через MSVC в текущем Linux-окружении не запускался. Для этой проверки используйте `Sfera\out\build_release.cmd` из Visual Studio 2022 Developer Command Prompt.
